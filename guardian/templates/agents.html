Active Cgroup Agents

Cgroup agents have 6-layer security — Landlock is the primary enforcer
Layer Enforcement Visible in Events?
Landlock LSM Inode-level file access (symlink-immune) No — silent
Seccomp BPF Blocks io_uring, mount, namespace escape No — silent
eBPF LSM hooks file_open, bprm_check, socket_connect Yes
eBPF tracepoints openat, execve, connect monitoring Yes
Cgroup isolation Resource limits, unspoofable identity N/A
PR_SET_NO_NEW_PRIVS Prevents SUID escalation N/A

Landlock and seccomp block silently — denials don't appear in the Events page or daemon logs. If an agent gets "Permission denied" but no BLOCKED event appears, the access was denied by Landlock (missing path in allow list) or seccomp (blocked syscall). Run guardian-launch with RUST_LOG=info to see the full Landlock ruleset at startup. Use strace -f -e trace=openat <cmd> to find which file access is failing, then add it to the allow list on the Policy page.
